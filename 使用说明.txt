媒体存档 / X Image Saver v1.2.1

用途
在 X（推特）图片、动图或视频上右键，通过「媒体存档 · 保存到」存入预设文件夹。
支持 Windows 上任意可写目录、中文路径、多个磁盘、最多 20 个目录。

从旧版升级
1. 等待正在保存的任务结束，关闭扩展设置页。
2. 将新版的 extension 文件夹覆盖到原来加载的 extension 文件夹。
   或者直接使用本次工作区更新后的 outputs\x-image-saver\extension。
3. 从 v1.2.0 升级到 v1.2.1，不需要重装小助手；本机助手继续为 v1.2.0。
   若本机助手仍低于 v1.2.0，双击新版 install.cmd，安装助手与 GIF 转码工具。
   已有 folders.json 会保留。
4. 打开 chrome://extensions，点击此扩展卡片上的刷新/重新加载按钮。
   如 Chrome 提示新增网站权限，请启用扩展并允许本功能所需的网站访问。
5. 刷新已经打开的 X / Twitter 页面，再开始右键保存。
扩展 key 和 ID 保持不变；从原位置重新加载即可保留扩展设置。
如果移动了扩展目录，可以移除旧扩展，再加载新 extension；本机助手的目录配置仍在。

安装（64 位 Windows 10 / 11，桌面版 Chrome 123 或更新版本）
1. 把整个压缩包解压到一个固定位置，例如 Documents\XImageSaver。
   不要仅从压缩包预览窗口运行脚本。
2. 双击 install.cmd，按照窗口提示完成本机助手安装。
   不需要管理员权限，不需要安装 Python 或 Node.js。GIF 转码工具已随包提供。
3. Chrome 地址栏输入 chrome://extensions 并打开。
4. 开启右上角「开发者模式」，点击「加载已解压的扩展程序」。
5. 选择解压文件夹里的 extension 目录（其中有 manifest.json）。
6. 在扩展菜单中点击「媒体存档」，打开设置页。
7. 确认页面显示「本机助手已连接」。点击「添加目录」，选择文件夹。
   修改菜单名称，如「插画」「角色 A」「参考素材」，然后点击「保存设置」。
8. 打开 x.com，在图片或视频画面上右键，展开「媒体存档 · 保存到」，选择目录。

使用细节
- 右键菜单在 X、Twitter 和 pbs.twimg.com 页面显示，支持图片、视频和播放器覆盖层。
  对空白处右键不会开始下载；必须右键要保存的媒体画面。
- 视频或动图画面右键会恢复 Chrome 的右键菜单，避免推特自定义菜单挡住扩展入口。
  按住 Shift 再右键，可继续使用推特自己的视频菜单。
- 图片来自 pbs.twimg.com，视频来自 video.twimg.com。没有接入第三方下载网站。
- 视频选择当前识别到的最高码率 MP4；可能低于网站 HLS 提供的最高分辨率。
  原本就是 GIF 的图片保留 GIF；X 用视频承载的动图默认转换为真正的循环 GIF。
  动图识别依据页面媒体类型、GIF 标签，以及动图专用封面或视频地址。
  转换保留完整时长，使用 15 帧/秒、最长边 720 像素（不放大小尺寸），GIF 为 256 色。
  画质与原 MP4 不完全相同，GIF 没有声音，文件体积通常更大。
  在设置页关闭「动图保存为 GIF」并保存设置，可改为保存源 MP4。普通视频保持 MP4。
  无法识别动图类型时仍会按普通视频保存；刷新页面、播放一下，再重新右键。
- 支持具有 MP4 地址的普通推文视频和动图。直播、仅 HLS、DRM 和站外视频不支持。
- 优先原图：对推文媒体图片尝试 name=orig；请求失败时尝试右键图片的当前地址。
  保存结果会注明回退到当前尺寸。不能保证每个链接都有更高分辨率的版本。
- 图片文件名使用媒体编号；视频使用推文编号及视频文件名。
- 根据实际图片字节识别 JPG、PNG、WebP、GIF、AVIF，不会把 HTML 错误页当图片保存。
- 同名时加 (1)、(2)…，不覆盖已有文件。不做内容去重。
- 图片最大 20 MB，源视频最大 512 MB，转换后 GIF 最大 256 MB。
  转码最多等待 5 分钟；失败或超限时报告错误，不自动改存 MP4。
  目录需先存在；选择窗口可以创建新目录。
- 下载由 Chrome 发起，使用浏览器网络/代理配置。视频分块传输，不整段装入消息。
  视频下载中会出现 .xs-随机编号.p 临时文件；GIF 转码还会生成 .xp-、.xg- 临时文件。
  下载和转换完成后才生成最终 MP4 或 GIF；转换采用两次读取生成调色板及动图。
  取消、下载失败或连接正常关闭时清理临时文件。强制结束进程或断电时可能遗留临时文件。
- 成功或失败会尝试显示系统通知；设置页保留最近 10 次操作结果。
  没有通知时，请查看设置页的「最近保存」。文件不会进入 Chrome 下载列表。
- 点击新版的保存成功通知，打开 Windows 资源管理器并选中刚保存的文件。
  如果文件已移动或删除，但原目录仍存在，则打开该目录。
  下载开始通知和下载失败通知不会打开目录；升级前的旧通知没有文件位置关联。
  通知位置记录保存在扩展本地存储中，保留最近 200 条成功通知，后台休眠后仍可定位。
  若原目录已从配置中移除、路径已更改或磁盘离线，则显示无法打开的提示。
  打开目录失败不会把原先的下载成功记录改成失败。
- 设置页中添加、修改、删除或排序目录后，均需点击「保存设置」。
- 动图或视频开始下载、GIF 转换开始和保存结束时会尝试通知你。
  网络连接等待超过 60 秒或下载总耗时超过 30 分钟会中止。
- 本机助手仅在保存、目录选择或设置检测时启动；任务结束后退出，无常驻监听端口。
  GIF 转换期间会临时启动 ffmpeg.exe 子进程，使用本地文件，不访问网络。
  X 页面上有轻量脚本识别媒体信息，它与本机助手是两部分，不会自动下载浏览到的媒体。

权限与安装位置
- 扩展权限：右键菜单、本机通信、本地配置、系统通知。
- 网络范围：pbs.twimg.com（图片）、video.twimg.com（视频）、cdn.syndication.twimg.com（公开推文嵌入信息）。
- 页面脚本仅在 X / Twitter 域名运行，观察页面已收到的媒体元数据，并记录右键目标。
  仅保留封面、视频类型、推文编号和 MP4 地址；不转发 Cookie、请求头、登录凭据或推文正文。
  媒体缓存仅在当前页面内存中；地址验证仍在扩展和本机助手执行。
- 本机助手安装在 %LOCALAPPDATA%\XImageSaver，转码工具在其 ffmpeg 子目录。
  安装前校验 FFmpeg 二进制 SHA-256，转码工具来源及许可见 native/ffmpeg。
- 仅注册当前用户的 HKCU\Software\Google\Chrome\NativeMessagingHosts\com.local.x_image_saver。
- 文件夹配置为本机助手目录中的 folders.json；菜单和近期结果保存在扩展本地存储中。
- 完成通知和对应文件路径也保存在扩展本地存储中；网页不能调用打开文件位置功能。
  本机助手仅允许定位当前已配置目录内的支持格式文件，不会执行下载文件。
- 安装脚本使用进程级 ExecutionPolicy Bypass，不改变系统执行策略。
- 内置的是自用、未签名的小程序及源码，没有上架 Chrome 商店。

常见问题
本机助手尚未连接：
  先运行 install.cmd，再在设置页点击「重新检测」。
  若修改了 manifest.json 中的 key，必须重新运行 install.cmd；请保留原来的 key。
  如遇系统防护拦截，请先核对包内源码或提示，不要为了安装关闭系统保护。
content.js 提示 XImageSaverMedia 未定义或解构失败：
  升级到 v1.2.1，完整覆盖 extension 文件夹并在 chrome://extensions 重新加载。
  随后刷新已经打开的 X 页面，旧页面里的旧脚本不会因文件更新而自动替换。
  新版两个页面脚本均自包含，不再依赖 globalThis.XImageSaverMedia。
  Chrome 扩展错误页会保留旧记录；可以先清除旧错误，再刷新页面复查。
扩展无法加载：
  选择包含 manifest.json 的 extension 文件夹，不能选择 extension\icons。
媒体菜单没出现：
  确认扩展已启用并有此网站权限；菜单可能折叠在扩展名称下。
  若仍弹出只有「复制视频地址」等选项的推特菜单，确认扩展为 v1.1.1 或更新版本，
  在 chrome://extensions 重新加载扩展，并刷新当前 X 页面。
没有找到视频地址：
  升级后必须刷新 X 页面，再播放一下视频并重新右键。
  当前页面媒体信息优先；识别不足时会尝试公开嵌入接口，后者并不支持所有推文。
  私密、受限或嵌入接口无法访问的推文，需要当前页面提供可下载的 MP4 地址。
  同一推文有多个视频时，按右键封面定位；无法可靠区分时会报错，不随意保存第一个。
提示本机助手需要升级：
  双击新版 install.cmd；仅刷新 Chrome 扩展不会升级已安装的小助手。
下载动图仍是 MP4：
  确认扩展已升级到 v1.2.0、运行了新版 install.cmd，并刷新 X 页面。
  设置页的「动图保存为 GIF」应勾选并保存；连接状态应提示 GIF 转码已就绪。
  旧版本已经保存的 MP4 不会自动变成 GIF，需要升级后重新下载该动图。
  不要只修改文件后缀；那样不会改变实际格式。
GIF 转换失败：
  查看最近保存的具体错误。检查转码工具是否被系统隔离、剩余磁盘空间是否足够。
  长动图可能超过 5 分钟或 256 MB 限制；可关闭「动图保存为 GIF」后改存 MP4。
点击完成通知无法打开目录：
  确认已经运行新版 install.cmd；本功能需要 v1.1.2 或更新的本机助手。
  测试时请点击升级后新产生的保存成功通知。旧通知没有文件位置记录。
  检查保存盘是否在线，原目录是否仍存在且仍在扩展目录配置中。
升级安装时提示文件被占用：
  等待下载结束、关闭文件夹选择窗口和设置页，再重试安装。
保存失败：
  查看设置页的最近结果。检查目标盘是否在线、目录是否存在、是否可写。
  下载错误则检查浏览器网络或代理。若媒体链接已过期，刷新推文再试。
移动了解压文件夹：
  在 Chrome 扩展管理页移除旧扩展，再从新位置加载 extension。
  key 保持不变则扩展 ID 稳定，本机助手无需重新注册。

卸载
双击 uninstall.cmd，再在 Chrome 扩展管理页移除「媒体存档」。
卸载脚本保留 folders.json 和所有已保存的媒体。

开发与验证
- extension/ 是可直接加载的扩展，使用 Manifest V3 与标准 JavaScript，安装时无需构建。
- extension/media-core.js 是具名导出模块，后台直接导入；页面脚本包含它的私有副本。
  scripts/content-runtime.js 与 scripts/page-observer-runtime.js 保存页面逻辑源码。
  修改这些源码后，在包目录执行 npm run build，生成两个完整的页面脚本。
  构建只需 Node.js，不下载依赖；npm test 会检查生成文件与源码是否一致。
- native/XImageSaverHost.cs 是本机助手源码，基于 Windows 自带 .NET Framework。
- 在包目录中，Node.js 22.8+ 可执行 npm test。
  Python 与 Pillow 可执行 python tests/native_test.py，真实转码测试调用随包 FFmpeg。
- native_test.py 在系统临时目录测试，不写入用户的收藏目录。
- 安装脚本兼容性测试：python tests/installer_test.py。
- 安装脚本提供 -ValidateOnly 参数，仅验证配置解析及扩展 ID，不复制文件或注册助手。
  -ValidateConverterOnly 仅校验转码工具哈希与系统位数，同样不执行安装。
- 本机助手重新编译示例（在包目录中执行）：
  C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe /nologo /target:winexe /codepage:65001 /out:native\XImageSaverHost.exe /reference:System.Web.Extensions.dll /reference:System.Windows.Forms.dll /reference:System.Drawing.dll native\XImageSaverHost.cs

v1.2.1 修复
移除 content.js 和 page-observer.js 对全局 XImageSaverMedia 对象的启动依赖。
每个页面执行环境只加载一个完整脚本，所需解析函数在同一闭包中初始化。
后台改为直接导入媒体解析模块的具名函数；不再读取全局共享对象。
通过内置构建脚本从同一份核心源码生成页面脚本，防止解析逻辑分叉。
扩展 ID、权限、目录配置和 v1.2.0 本机助手保持兼容；此次仅需重新加载扩展并刷新网页。

v1.2.0 更新
识别 X 的 animated_gif 媒体后，默认将源 MP4 转换为真正 GIF。
增加「动图保存为 GIF」设置；普通视频保留 MP4，原 GIF 图片保留原格式。
附带经来源哈希验证的 FFmpeg 9.0.2 x64，采用两遍调色板转码、完整时长、
15 帧/秒、最长边 720 像素、256 MB 输出上限与 5 分钟超时。
转码失败时清理临时文件；完成通知定位最终 GIF，同名文件继续编号保留。
运行新版 install.cmd 升级本机助手与转码工具；已有目录配置保持兼容。

v1.1.2 更新
点击保存成功的 Windows 通知，打开对应文件夹并选中文件。
通知与路径关联持久保存，支持后台休眠后点击和多个下载通知分别定位。
本机助手增加 revealSaved 操作与路径校验；保留文件不存在时打开原目录的回退。
本次必须重新运行 install.cmd 升级小助手；扩展 ID、权限和已有目录配置保持兼容。

v1.1.1 修复

Shift + 右键保留推特原菜单，图片及非视频页面保持原有行为。

v1.1.0 更新
